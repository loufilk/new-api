# 工单邮件通知（默认关闭，未启用生产）

基于 `loufilk/new-api@d387e40e8090d714fd9cd6809162160ca8c3b8c8` 的独立本地实现，
不包含分组改名或模型测试开关修改。源码不会自动部署、配置真实SMTP或发送真实测试邮件。

## 使用与配置

- root：**系统设置 → 内容 → 工单邮件通知** (`/system-settings/content/support-email`)。
  设置持久化在专用版本化单例表，不依赖各节点的周期配置缓存。默认关闭；升级不会通知旧工单。
- 先在现有邮件设置配置SMTP，再填写1–5个管理员收件地址、准确的公开HTTPS站点origin，显式启用。
  站点地址只能是origin，如 `https://api.example.invalid`，不得带路径、query、fragment、userinfo、通配符。
  不采用请求Host、转发Host或用户输入的跳转地址。
- SMTP状态只显示配置完整性，不展示密码，也不是实际投递成功的保证。本功能只使用当前选择的SMTP，
  **不在Resend失败时回退到SMTP，也不在SMTP失败时回退到Resend**。选中Resend时不允许启用本功能；
  已启用后改成Resend，待发送记录按安全错误重试。若需要Resend通知，请另行实现/验收而不是暗中切换。
- 远程SMTP要求TLS/STARTTLS且验证服务器证书；仅loopback开发可明文。缺半套认证信息也视为未配置。
  没有“自动发送测试邮件”按钮。真实凭据配置、收件人确认与首次生产投递必须另行授权。
- 收件人每人独立一封，不公开其他地址，不使用CC/BCC。
- `/support` 显示自己的接收邮箱、验证状态和独立通知偏好。未绑定/未验证时引导到**账户安全 → 邮箱**。
  旧账号可在“更换邮箱”填入同一地址补验证；验证仍要求现有安全proof、验证码、限次、到期、单用和唯一归属。
  用户关闭工单通知不影响密码重置、验证码或强制账户安全邮件。

## 什么会发邮件

- 新工单、客户追加回复：仅通知root明确配置的管理员地址，不盲发全部管理员账户。
- 管理员公开回复：仅通知该工单所有者当前已验证且未禁用的邮箱，用户可选择关闭。
- 状态变更、已读、内部笔记/未知作者角色、系统事件不触发邮件；不解析收件邮箱、不把邮件回复导入工单。
- 邮件只有工单编号、事件类型、固定站点 `/support?ticket=ID` 链接与登录提示。
  **不含工单标题、正文、请求、token、IP、附件或客户身份。** 查看详情仍由站点会话/本人或管理员权限校验。
  文字和HTML两种内容，HTML转义；邮件说明不能直接回复此自动通知。

## 收件邮箱的可信依据

`User.Email` 本身不是验证证明。新增隐藏的证明地址、版本与时间：
- 本地验证码注册（成功原子消费）、当前安全邮箱绑定和新建内置Google权威邮箱账号才建立证明。
- Google继续只采纳其权威Gmail/签名Workspace邮箱；第三方 `email_verified` 或任意profile字段不够。
- 不为历史邮箱、普通OAuth资料或管理员直接填写的邮箱批量回填证明。
- 更换/解绑邮箱会清除证明并推进版本；旧快照和旧的在途绑定挑战不能恢复它。
- 派发前在主库锁定并重核账户状态、唯一邮箱归属、当前地址、证明版本及偏好版本。
  地址或证明变化会取消旧记录，**不会把旧通知改投新邮箱**。

## 耐久队列、失败与并发边界

工单/消息与outbox事件同一个数据库事务。数据库写失败时该次操作不被报告成功；
成功提交后的SMTP失败不会回滚工单/回复，也不会让HTTP请求等待SMTP。

- 消息ID + 收件类别/地址唯一键负责事件幂等；重复消费不会新建相同通知。
- 同工单、同收件人、同配置/证明版本已有待发通知时，新事件记为coalesced；已有邮件链接展示最新线程。
- 多节点CAS领取，120秒租约；真正发送准入时续租。SMTP使用准入时刻起算的绝对30秒截止时间，
  进程暂停后不能重新获得30秒发送窗口。进程退出/崩溃后由新节点恢复到期租约。
- 每收件类别/地址至少间隔60秒；管理员每24小时窗口最多120次、客户30次派发尝试。
  超限延期而非绕过，所有事件创建7天后不再投递。人工重试同样受当前资格、限流与有效期约束。
- 每轮最多6次尝试，30/60/120/240/480/960秒指数退避（同时受限流）；耗尽进入dead。
  root可查看安全错误码/次数/下次时间、重试dead或取消未准入记录，操作写审计，不显示私密正文、地址或凭据。
- 配置改变（启停、管理员地址、站点origin）推进版本并取消旧pending/retry/leased/dead；重新启用不补发旧积压。
  用户偏好改变同样推进版本并取消其未准入回复邮件。
- 准入事务采用 `settings → user → preference → outbox → rate` 锁顺序，
  账户/邮箱证明变化与 `sending` 转换线性化，不跨SMTP持有数据库锁。
- **sending提交是派发准入边界，不是物理投递完成。** 在此之后关闭/改地址/取消不能撤回已获准邮件；
  因而界面不对sending提供取消。SMTP配置在准入之后读取，仍受该次绝对截止时间约束。
- SMTP服务器已接受DATA但250确认丢失、或成功后数据库结果未写入时，无法辨别是否投递，重试可能重复。
  重试保持稳定Message-ID，**这是at-least-once，不承诺exactly-once**；接收端也未必按Message-ID去重。
  收到DATA成功后QUIT失败不重试。

所有执行节点必须升级，且必须使用共享主数据库；旧binary不具备新队列保护。
诊断记录含最小服务器端收件快照，应按现有数据库/备份权限保护；界面不公开该快照。
当前不自动删除诊断历史；7天是投递截止，不是数据删除承诺。

## 验证与边界

测试仅使用自有临时loopback PostgreSQL 18.6、合成用户及本地fake SMTP；未操作真实邮箱、生产数据或真实凭据。
覆盖事务回滚、重复事件、双节点CAS、重启恢复、锁屏障下邮箱变更/准入顺序、旧/过期租约、绝对截止、
SMTP配置变更、单收件人/恶意内容、失败重试/死信、root与普通用户权限、深链和前端状态回归。
精确执行命令、结果、fresh/已发布基线升级/重复启动、最终嵌入binary HTTP证据见私有交付包。

未验证：真实SMTP厂商投递率、生产反代/真实浏览器跨站Cookie与视觉、MySQL和SQLite兼容矩阵。
初始编译探测误触发过model/service默认内存SQLite TestMain但没有运行用例；它不是验收，后续实际用例均经PG wrapper。
不宣称全仓测试或三数据库已认证。没有commit/push/PR/部署，因此没有本候选GitHub CI。
