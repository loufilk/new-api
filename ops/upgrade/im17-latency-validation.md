# im.17 首字与后台性能验收

基线是 im.16 `36e4fac3af44e5640dda2e91b0cf00111e6379ed`。依赖候选和应用修复分开运行。PostgreSQL、Redis、模拟上游及客户端全部使用隔离环境及纯合成数据；没有生产查询、真实 Key、供应商或采购。镜像升级前的检查见 [im.17 运行时](im17-runtime.md)，报表迁移与回退见 [报表刷盘](im17-dashboard-flush.md)。

| 场景 | PG / Redis | 540 RPM 混合，客户端首字 P95 | 600 RPM 混合，客户端首字 P95 | 600 RPM，后台列表 P50 / P95 |
|---|---|---:|---:|---:|
| im.16 基线 | 18.6 / 8.8.0 | 355 ms | 366 ms | 275 / 556 ms |
| 原 im.16 行为，仅升级后端依赖 | 18.7 / 8.10.3 | 558 ms | 385 ms | 230 / 544 ms |
| im.17 修复，翻页按新 UI 路径 | 18.7 / 8.10.3 | 240 ms | 172 ms | 5 / 269 ms |

每组使用 602,000 条合成历史日志、一个热点测试 Key、三名模拟后台读者；每档 12 秒。每个档的请求数为 108 或 120，三组各 459 次（含三次单帧间隔测试）均成功，等额测试钱包差额为 22,950 单位，未出现结算异常。旧客户端默认要精确总数，im.17 的“翻页”比较使用与新 UI 一致的同筛选结果复用：每个读者初次仍取精确统计和总数，短期内后续只取页。数值有运行噪声，不是生产容量证明，不能据此判定换 PostgreSQL 或 Redis 一定更快或更慢。

**独立因果复现**：同一模拟上游在首正文后停 800 ms，im.16 两组仍额外等待约 801 ms；im.17 从模拟上游首正文写出到客户端读到首正文为 0.91、1.39、5.12 ms。网关分别记录 FRT/TTFT=48/54、49/56、50/52 ms，客户端约 55、60、54 ms。TTFT 是网关入口至首个有效下游 flush，不是 TCP 建连或浏览器实际显示时刻。FRT 保留作旧指标。

**相关回归**：

- 原生 Chat：即刻角色、正文/推理/工具转发；明确区分控制帧与正文；usage 隐藏保持；合并结束/用量、部分丢失、断线、JSON 原字段与账务证据。原来的 Claude/Gemini 转换终止行为保留。
- 日志：新前端同权限与筛选条件下 30 秒内复用总数/统计，翻页不再重复 COUNT/SUM；旧 API 默认返回精准总数，切换账号/角色和过滤不会复用结果。深分页仍用 OFFSET。
- PG18.6/18.7 报表：持数据库锁与请求入队分离、持久化失败后原批重试、提交确认丢失但不双计、新旧库各连续迁移两次、长标签和历史重复/NULL 保留。未提交进程内报表仍不是持久队列，钱包账本、扣费与退款数据未改动。
- 这次不改分组版本的 15 次读取、热点账户账前验证或智能路由同步指标；后续应该按真实流量分布测，并保留撤权和资金约束。不能用短压测宣布 500–600 RPM 阈值消失。

依赖优先取官方稳定版。涉及持久凭据格式、兼容 API、既有工具链校验基线、React Table 大版迁移等项，保留已验证的兼容版本，未宣称所有包无例外都到最新。
