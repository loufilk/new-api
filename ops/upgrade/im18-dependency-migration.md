# im.18 依赖迁移

从 im.17 `d89acdd4179a08c6b8f1957370720aa1877baa27` 分出。此分支只迁移依赖和直接受影响的使用方式；不切生产数据库、网关或商户配置。

| 范围 | 版本与兼容性做法 |
|---|---|

| 翻译 | i18next 27.2.1、react-i18next 18.0.3；收窄文本翻译回调的类型，不修改实际语言资源，保留语言切换及原始错误文本规则。 |
| 前端检查 | Oxlint 1.94.0；保留现有规则选项。与原上游例外分开，冻结一份 im.17 已存在的新增 React Compiler 诊断快照；只认原文件哈希和原诊断，无全局禁用、无新增诊断豁免。通过门禁不等于历史诊断已经清零。 |

| 支付 | Stripe Go 87.2.0、Waffo Go 2.3.0；Stripe 保持原商户 API 版本 `2025-02-24.acacia`，不把 SDK 升级混成商户 API 切换。用隔离 PostgreSQL 和模拟商户核对金额、签名、重放、回调失败重试和重复入账，不触发实际支付。 |
| 授权和运行监控 | Casbin 3.11.0 使用 Apache 官方发布源码，而不是与同号版本不一致的旧代理工件。gopsutil 4.26.10 保留生产已有的 Linux host 内存占用口径和 cgroup 优先级，避免阈值被依赖升级改变。 |

使用验收线 Go 1.27.4、Bun 1.4.4、Node.js 26.13.1、PostgreSQL 18.6/18.7 和 Redis 8.10.3。Redis 8.12 RC、PostgreSQL 19 RC 不属于此次稳定运行时升级。第三方间接依赖仍尊重各库的兼容约束，不强行对整个传递图做跨大版本覆盖。

发布前仍须确认实际环境的 CI、Stripe/Waffo 商户沙箱、代表性 Passkey 设备与现网配置；本次不是线上容量或真实支付验收，不变更原 im.17 分支。

## 迁移中发现并修复

- 浏览器前进、后退或外部重置筛选不会再被旧的防抖输入覆盖；中文输入法的中间态不会提交。表格的展开、筛选标签和行选择覆盖真实交互回归。
- 已确认的分组改名和价格修改不会被同一份旧缓存回放撤销，仍保留版本冲突和明确重载流程。
- Waffo 下单结果未知、或收到已验证的支付中通知时，保持订单待处理。只有明确的拒绝或关闭才可结束等待；只有通过签名和金额、币种、商户等订单绑定校验的成功事件才能入账。这次不补账或改写历史失败订单。

登记核对时，Web/Electron 及自有 Go 模块共 172 条直接依赖清单记录与各自规范来源的 `latest` 相同（同一库在多个模块声明可重复计数，Apache Casbin 按实际替换工件计）。

## 云电脑验收

- 受影响的 Web 范围覆盖 206 个测试文件。首轮 2,721 项通过，5 项失败集中在两个文件；供应商表格修复及旧版可复现的渠道排序异步测试竞态修正后，分别重跑两个完整文件（6 项、35 项），均通过。不是一次整库全绿。
- 最终源码以冻结锁文件安装，前端类型检查、Lint、前端生产打包、Go 内嵌前端构建均通过。用 PostgreSQL 18.7 和 Redis 8.10.3 启动最终产物，健康检查、流式调用及用量扣减通过，余额相符且无结算或赠金一致性错误。
- 在 PostgreSQL 18.6 和 18.7 分别验证旧版发起的 Passkey 仪式可跨版本完成，并验证模拟支付的补到回调与重复通知只入账一次。未接真实商户、Passkey 硬件或生产流量；不据此宣称吞吐或首字延迟改善。
